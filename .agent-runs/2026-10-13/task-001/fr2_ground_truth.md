## 4. 文档示例自洽性判定 —— **不自洽，属占位值**

### 4.1 文档示例原文（`docx_dump.txt:301`）

```
{"satisfaction_overall": {"table_id":"att1_satisfaction","row_count":214,"missing_rate":0.0187},
 "complaint_count":     {"table_id":"att5_complaint","row_count":214,"missing_rate":0.0},
 "profit_actual":       {"table_id":"att6_profit","row_count":214,"missing_rate":0.0093}}
```

同文档另一处示例（`docx_dump.txt:190`，`/api/v1/intake/audit` 响应）为 `{"conflicts":7, "mapping_rows":63, ...}`。

### 4.2 反证一：同一个 214 套在三个行数各异的附件上（决定性证据）

`214` 被同时赋给 **附件1 / 附件5 / 附件6** 三个字段。但本目录三者的真实行数**互不相等**：

| 附件 | 真实物理数据行 | 真实有效门店行 |
|---|---|---|
| 附件1 | 160 | 157 |
| 附件5 | 157 | 157 |
| 附件6 | 158 | 157 |

> 三个不同附件**不可能同时等于 214**。若 214 是真值，则三表应同源；实测三表行数两两不同 → `214` 不是本目录真值。

### 4.3 反证二：`missing_rate` 与同一行的 `row_count` 互斥

反推「空值个数 = row_count × missing_rate」：

| 字段 | 文档 row_count × missing_rate | 隐含空值 | 若按真实口径（空值/真实行） |
|---|---|---|---|
| att1 满意度 | 214 × 0.0187 = 4.0 | 需 4 个空值 | 实测 **3 个空行 / 160** = **0.0188**（≈文档 0.0187，且需 3 而非 4） |
| att5 投诉量 | 214 × 0.0 = 0 | 需 0 个空值 | 实测 0 / 157 = 0.0 ✅（但 214 口径下也=0，无区分度） |
| att6 利润 | 214 × 0.0093 = 2.0 | 需 2 个空值 | 实测 **1 / 158 = 0.0063**（≠0.0093，两者都对不上） |

- **附件1**：文档 `missing_rate=0.0187` 恰好对应真实口径 `3/160`（`f"{3/160:.4f}" = 0.0187`）；而 `214` 口径需 4 个空值，实测只有 3 个 → **同一行内 `row_count` 与 `missing_rate` 指向不同分母**。
- **附件6**：文档 `0.0093` 与真实 `1/158=0.0063` 不符，也与 `2/214` 勉强凑出的 0.0093 不符（真实只有 1 个空行）。

### 4.4 反证三：文档自己声明这些数字是占位

`docx_dump.txt:301` 结尾原文（同段）：

> 「上表中的数字必须由 `python -m mmagent.cli freeze-golden --write` 在冻结日一次性生成后人工核对并签署，**不得手填猜测值**。」

→ 文档作者自己把这些示例值定性为「非权威、须重新生成」。结合 §4.2/§4.3，可确认 `214 / 63 / 7` 是**形态示意占位值**，**不是**本目录任何口径的真值。

### 4.5 结论

**`row_count=214`（及 `mapping_rows=63`、`conflicts=7`）无法从本目录任何文件任何口径推出 → 判定文档示例不自洽。**
不得据此冻结 golden；`tests/golden/intake/spotcheck_expect.json` 必须由 `freeze-golden --write` 依真实数据（本报告 §1 真值为比对基线）重新生成并人工签署。
